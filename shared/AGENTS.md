# shared/ — the wire contract

The manual for this package. The repo-wide manual is the root
[`AGENTS.md`](../AGENTS.md); read that first, then this for what is specific to
`shared/`.

`shared/` is the canonical **stdlib-only** wire protocol (`screenreader-wire`):
envelope + per-command dataclasses + `from_dict` validator + JSON-lines
helpers, plus `schema.py`, which generates the published
[`specs/wire/v1/schema.json`](../specs/wire/v1/schema.json) from the dataclasses
and is **not** synced into the addon. It runs on desktop CPython and is
unit-tested once.

It is the one package both halves depend on, and neither half imports: the
bridge gets a verbatim *copy* of `protocol.py`, and the server generates its own
binding from the published schema. What is shared between implementations is the
contract, not code.

## Why the package is named for the contract

It is `screenreader_wire` — not `nvda_mcp_wire`, which it was until
**2026-08-29**, and not `wire` or `protocol`.

Named for the **contract** because the reader it used to be named after is only
the first binding of three: Python here, Go in `server/adapters/wire/` generated
from the schema, Swift in lane 3. Named at **length** because of invariant 1:
this package is copied verbatim into NVDA's interpreter, where it shares
`sys.modules` with every other add-on, so a short name is collision bait and a
collision there is not a name clash, it is somebody's screen reader. The module
inside it stays `protocol`, so both halves address the contract through a module
of that name.

Board entry **11.36**, [spec
0045](../specs/0045-a-wire-module-named-after-the-contract.md).

## The wire shape may still change in place

**`PROTOCOL_VERSION` 1 is PRE-RELEASE, and a wire shape may be changed in
place** — see [`specs/wire/v1/protocol.md`](../specs/wire/v1/protocol.md) §8. There
are no external consumers: both halves ship from this repo and `hello` is an
exact-equality check, so a changed shape costs a rebuild of both, not a
migration. Only once a **non-Python bridge** depends on the contract does an
incompatible change require a version bump and a new `specs/wire/vN/`.

This is here because the policy was written in §8 of the published contract,
which a session implementing a *bridge feature* has no reason to open — so
"additive only" gets assumed, and a cleaner shape gets designed around instead
of taken. Prefer the right shape and change it; say so in the PR. The version
number exists to stop a **stale bridge/server pairing**, not to freeze shapes.

## The invariants that govern this package

Three of the root manual's hard invariants are about this directory, and they
are the reason it looks the way it does. They are stated there, not restated
here, so there is one copy to keep true:

- **Invariant 1 — `shared/screenreader_wire/protocol.py` stays stdlib-only.**
  It is copied verbatim into the addon and runs inside NVDA's interpreter,
  sharing `sys.modules` with every other addon.
- **Invariant 2 — the addon never edits its copied `protocol.py`.** Edit the
  canonical file here; the copy is a gitignored build artifact regenerated by
  `bridges/nvda/sync_shared.py`.
- **Invariant 4 — type hints everywhere, pyright strict.** This package is pure,
  so all of it is strict-checked; there is no exempt edge here.

Two root rules land here too: enumerations are `enum` (the wire enums
`CaptureMode` and `Command` are `enum.StrEnum` so JSON stays plain, while
`Request.cmd` stays a raw `str`), and every import names its own file —
`from screenreader_wire.protocol import ...`, never a re-export facade, so both
halves address the wire contract through a module named `protocol`.

## Tests

`tests/unit/` mirrors the package file for file, exactly as the root manual
describes: `shared/tests/unit/test_protocol.py` ↔
`screenreader_wire/protocol.py`. The commands are `uv run poe shared` and
`uv run poe shared-types`; see
[`docs/dev-commands.md`](../docs/dev-commands.md) for what they run underneath.
