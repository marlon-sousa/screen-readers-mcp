# nvda-mcp-wire — the wire contract

The **canonical, stdlib-only** JSON-lines protocol that the `screenreader-mcp`
**server** and a **bridge** speak to each other. This package is the Python
side of it, and the source the published schema is generated from.

The package name predates the project's rename and the reader-agnostic
direction ([spec 0005](../specs/0005-multi-reader-direction.md)); the contract
itself has no NVDA in it. What a bridge is for is decided by the bridge, not
here.

## What is in it

Everything both halves must agree on lives in `nvda_mcp_wire/protocol.py`:

- the message envelope (`Request` / `Response` / `ErrorInfo`),
- per-command param and result dataclasses,
- a small generic `from_dict` validator (walks `typing.get_type_hints`, raises
  `ValidationError` naming the offending field path),
- `to_dict` and JSON-lines `encode_message` / `decode_message` helpers,
- the protocol version, the default port, and the enumerations — capture modes,
  capabilities and command names — as `enum.StrEnum`, so the JSON stays plain
  strings.

Two fields deliberately stay raw `str` rather than becoming enums, and both for
the same reason: an unrecognised value must degrade rather than crash.
`Request.cmd` does, so an unknown command yields a clean error instead of a
validation failure; and `persona` does, so the day a fourth persona is added, an
older bridge serves its general guidance instead of refusing the handshake.

Beside it, `nvda_mcp_wire/schema.py` generates
[`specs/wire/v1/schema.json`](../specs/wire/v1/schema.json) from those
dataclasses. That file is the **published contract** — it is what a second
implementation reads, and it is not synced into any add-on.

## Two implementations, one schema

The two halves are no longer the same language, and that changed what guarantees
the contract.

- **The bridge** (NVDA's embedded CPython) runs `protocol.py` itself. The add-on
  build copies it in verbatim, so the bridge and this package are the same
  bytes by construction.
- **The server** is Go. Its binding is **generated** from
  `specs/wire/v1/schema.json` into `server/adapters/wire/wire.gen.go` and is
  private to the server, because what is shared between implementations is the
  contract, not the code.

So the old same-bytes argument covers only one side now, and two gates stand in
for it on the other:

| Gate | What it proves |
|---|---|
| `uv run poe gate-schema` | The committed `schema.json` still matches `protocol.py`. |
| `uv run poe gate-binding` | The committed Go binding still matches `schema.json`. |
| `uv run poe conformance` | The real Go binary and the real Python bridge agree over a real pipe and a real socket. |

The conformance tier is the successor to the same-bytes guarantee, and it is
not ceremonial: it is the only place where **both** implementations of
`specs/wire/v1/` are real, so a bug in the generated binding — invisible to
every tier whose bridge is a Go fake encoding with that same binding — has
somewhere to surface. It found one on its first run.

## Why stdlib-only

`protocol.py` is copied straight into the add-on and runs inside NVDA's
interpreter, sharing `sys.modules` with every other add-on installed on that
machine. A third-party import here would become a dependency of NVDA itself and
could collide with another add-on's copy of the same library. There is no
version of that trade worth making, so the rule is absolute: **no third-party
imports in `protocol.py`, ever.** The server may use third-party libraries; this
module may not.

## Running its gates

```sh
uv run poe shared      # the contract tests, pyright strict, lint, schema gate
```

or directly:

```sh
uv run --directory shared pytest      # the contract tests
uv run --directory shared pyright     # type-check (strict)
```

## Editing it

The canonical file is the one in this directory. The copy under
`bridges/nvda/addon/globalPlugins/nvdaMcpBridge/` is a **gitignored build
artifact**, regenerated by `bridges/nvda/sync_shared.py` — never edit it. When a
change here alters the shape, regenerate the schema and the Go binding in the
same commit, or the two gates above will say so.

What may be changed in place under `PROTOCOL_VERSION` 1, and what would cost a
version bump instead, is in [AGENTS.md](AGENTS.md) beside this file.
